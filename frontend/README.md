# Разработка интерфейса

`App.vue` — общая оболочка. Новые представления подключаются в `pages.js`, без изменения оболочки и навигации.

| Каталог / файл | Назначение |
| --- | --- |
| `views/` | Представления страниц: проекты, команда, управление и учетная запись |
| `pages.js` | Соответствие Django `page` и Vue-компонента, заголовки и параметры страниц |
| `views/props.js` | Общие входные параметры представлений |
| `layouts/AppHeader.vue` | Шапка и основная навигация |
| `layouts/ProjectSidebar.vue` | Навигация выбранного проекта и выход из него |
| `components/` | Повторно используемые формы и пагинация |
| `composables/usePageNavigation.js` | Состояние текущей страницы, переходы, POST, ошибки и уведомления |
| `api.js` | HTTP-запросы и CSRF |
| `lib/format.js` | Форматирование дат и разрешений |
| `styles/tokens.css` | Цвета, интервалы, радиусы и поверхности |
| `styles/app.css` | Компактный интерфейс поверх базовых стилей `static/app.css` |

## Новое представление

Создайте `views/ExampleView.vue`:

```vue
<script setup>
import { pageProps } from './props.js'
defineProps(pageProps)
defineEmits(['submit', 'navigate'])
</script>

<template>
  <section>
    <h1>{{ data.title }}</h1>
  </section>
</template>
```

Импортируйте компонент и добавьте запись в `pages.js`:

```js
import ExampleView from './views/ExampleView.vue'

// В объекте pages:
example: { component: ExampleView, title: 'Новая страница' },
```

Ключ `example` соответствует `name` маршрута Django и полю `page` JSON-ответа. На сервере новый маршрут добавляется в `config/urls.py` и `PAGES` в `core/frontend.py`. Новые поля ответа явно добавляются в `page_data()` / `object_data()` этого файла. Проверки прав и входных данных выполняются в Django.

Все представления получают `data`, `user`, `busy` и `options`. `data` — данные ответа, `options` — запись реестра `pages.js`. Для действий используются события:

- `$emit('submit', values)` отправляет форму на текущий URL.
- `$emit('navigate', '/somewhere/')` открывает страницу.
- `$emit('navigate', '/somewhere/action/', {})` выполняет POST без полей.

Обычные внутренние ссылки `<a href="...">` перехватывает общая навигация. Vue-компоненты не дублируют работу с CSRF, редиректами и сессией.

Для страниц внутри проекта сервер должен передавать проверенный на доступ объект `project` в контексте ответа. Адаптер преобразует его в `data.project`; общая оболочка автоматически показывает sidebar. Не храните выбранный проект отдельно в localStorage: контекст восстанавливается сервером по URL. Новые разделы регистрируются в `pages.js` и списке `sections` в `ProjectSidebar.vue`. Переход на страницу без `data.project` закрывает рабочее пространство проекта.

Для стандартной серверной формы используйте `FormView` в реестре. Параметры: `title`, `button`, `showSubtitle`. Для особой разметки создайте отдельное представление и используйте `PageForm` внутри него. `ConfirmationView` обслуживает подтверждения, `MessageView` — страницы результата.

## Стили

Сначала используйте существующие классы: `page-heading`, `panel`, `detail-grid`, `project-grid`, `table-wrap`, `button`. Стили конкретного компонента можно размещать в его `<style scoped>`.

Стеклянные поверхности сделаны статическими градиентами, рамками и небольшими тенями. `backdrop-filter` применяется только к шапке при ширине больше 768 px. При уменьшении прозрачности или движения в системных настройках размывание отключается; отдельные браузеры могут не поддерживать настройку уменьшения прозрачности. Нет фильтров SVG, непрерывных анимаций или зависимостей для визуальных эффектов. Производительность на слабых устройствах отдельно не измерялась.

## Запуск

```sh
npm run watch
```

Открывайте приложение через Django и обновляйте браузер после пересборки. Для готовой сборки: `npm run build`. Файлы `static/frontend/` генерируются; правьте исходники в `frontend/`.
