# Projectus: введение для разработчика

Краткий обзор текущего кода на 14 октября 2026 года.

## Что это за проект

Projectus — веб-сервис для ведения социальных и других проектов. Он объединяет описание проекта, команду, измеримые результаты, мероприятия и бюджет в одном рабочем пространстве. Пользователь регистрируется, подтверждает email и подаёт заявку на создание проекта. После одобрения сотрудником сервиса появляется проект, а заявитель становится его владельцем.

Основная связь между разделами: **цели и задачи проекта → мероприятия → достигнутые показатели**. Бюджет описывает расходы, а заявки на оплату могут быть связаны с мероприятиями.

## Что уже реализовано

- **Аккаунты:** регистрация, подтверждение email, вход, выход, восстановление и смена пароля.
- **Проекты и команда:** рассмотрение заявок, карточка проекта с целями, задачами и сроками, приглашения зарегистрированным пользователям, принятие и отзыв приглашений, индивидуальные разрешения участников.
- **Показатели:** количественные цели с единицами измерения и прогрессом; качественные результаты с текстовым описанием и отметкой достижения.
- **Мероприятия:** плановые и фактические даты, результаты, связи с задачами и показателями, фотографии и документы. После подтверждения мероприятие закрывается для изменений, а его количественные результаты включаются в показатели проекта.
- **Бюджет:** статьи и строки сметы, шаблоны, версии сметы, согласование изменений и переносов, учёт поступлений. Заявки на оплату проходят согласование выбранными пользователями; согласованные суммы резервируют средства. Исполнение фиксируется с реквизитами платёжного документа и подтверждающим файлом. Перевод денег через банк не реализован.
- **Управление сервисом:** заявки, пользователи, полномочия сотрудников и журнал действий.

Договоры проекта и «Мои договоры» пока представлены страницами-заготовками. Электронное подписание, грантовые заявки, автоматические отчёты, календарь/Гант и учёт занятости команды ещё не реализованы. Наличие разрешения в каталоге не означает, что соответствующий модуль готов.

## Как устроена архитектура

Это один Django-проект с приложением `core` и интерфейсом на Vue 3. Сервер хранит данные, проверяет права и выполняет бизнес-операции; Vue отображает страницы и отправляет формы. Vite собирает интерфейс в статические файлы, которые раздаются вместе с Django. Основная база — PostgreSQL; SQLite предусмотрена для локальной разработки и быстрых тестов.

Путь обычного действия: **Vue → маршрут Django → проверка доступа и форма → бизнес-операция → база данных → ответ для Vue**.

У страниц общий адрес для HTML и JSON: запрос с `Accept: application/json` получает данные страницы, обычное открытие — оболочку Vue с начальными данными. Это API страниц поверх серверных обработчиков. Формы отправляются как обычные поля, файлы — через multipart. Вход работает на сессиях Django, изменяющие запросы защищены CSRF. Для работы без JavaScript сохранены серверные HTML-шаблоны.

| Где смотреть | Что находится |
| --- | --- |
| `config/urls.py`, `config/settings.py` | Маршруты и настройки приложения |
| `core/models.py`, `core/migrations/` | Сущности, связи, ограничения данных и изменения схемы |
| `core/views.py`, `core/forms.py`, `core/services.py` | Аккаунты, проекты, команда, показатели и управление сервисом |
| `core/event_*.py`, `core/budget_*.py` | Обработчики, формы и бизнес-операции мероприятий и бюджета |
| `core/permissions.py` | Каталог разрешений и проверки прав |
| `core/frontend.py` | Явное преобразование серверных данных в ответы для Vue |
| `frontend/views/`, `frontend/pages.js` | Компоненты страниц и их реестр |
| `frontend/api.js`, `frontend/composables/` | Запросы, переходы, отправка форм и обработка ошибок |
| `templates/`, `private_uploads/` | Серверные шаблоны и приватные вложения |
| `core/test*.py`, `frontend/tests/`, `frontend/e2e/` | Серверные, клиентские и браузерные тесты |

## Правила, которые важно сохранить

- Владелец имеет все проектные права и управляет командой. Участникам выдаются отдельные разрешения, без фиксированных проектных ролей. Системные полномочия сотрудников не открывают доступ к чужим проектам, включая главный аккаунт.
- Проверки доступа выполняются на сервере: скрытой кнопки в интерфейсе недостаточно.
- Подтверждение мероприятия и финансовые переходы используют транзакции и блокировки записей. Повторное подтверждение не должно повторно начислять результат, а платежи не должны превышать доступные средства и лимиты сметы. Денежные вычисления выполняются через `Decimal`.
- Вложения скачиваются только через защищённые обработчики. Каталог `private_uploads/` нельзя раздавать публично.
- Цели и задачи пока хранятся списками в JSON-полях. В мероприятии сохраняется снимок выбранных формулировок задач, а не связь с отдельной моделью задачи.

Для первого знакомства пройди сценарий: регистрация → заявка → одобрение → приглашение участника → показатель → мероприятие → подтверждение результата. Затем изучи бюджет: смета → поступление → заявка на оплату → согласование → фиксация исполнения.

Инструкции запуска находятся в [README.md](README.md), добавления страниц — в [frontend/README.md](frontend/README.md). Часть README и бэклога описывает более ранние этапы; этот обзор учитывает имеющийся код бюджета. Тесты при подготовке обзора не запускались; проверка конкурентных операций на PostgreSQL остаётся отдельной задачей перед выпуском.
